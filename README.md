# Комп’ютерний практикум 1. Проєктування REST API та його реалізація

## Швидкий старт

Запуск API:

```bash
go run ./cmd/api
```

Swagger UI:

```text
http://localhost:8080/swagger/index.html
```

Base URL API:

```text
http://localhost:8080/api/v1
```

API key для POST, PUT, DELETE:

```text
X-API-Key: demo
```

Основні маршрути:

```text
GET    /api/v1/cats
GET    /api/v1/cats/{id}
POST   /api/v1/cats
PUT    /api/v1/cats/{id}
DELETE /api/v1/cats
DELETE /api/v1/cats/{id}

GET    /api/v1/shelters
GET    /api/v1/shelters/{id}
GET    /api/v1/shelters/{id}/cats
POST   /api/v1/shelters
PUT    /api/v1/shelters/{id}
DELETE /api/v1/shelters
DELETE /api/v1/shelters/{id}
```

Оновлення Swagger-документації:

```bash
swag init -g cmd/api/main.go
```

## Мета

Отримати навички проєктування та реалізації REST API вебзастосунку, що буде надавати доступ до декількох сутностей обраної предметної галузі.

## Завдання

- [x] 1. Студент самостійно обирає предметну галузь, котрій буде присвячена робота його комп’ютерного практикуму. Якщо студент не може самостійно обрати предметну галузь, він може звернутися за допомогою до викладача (лектора з дисципліни).

- [x] 2. В рамках обраної чи наданої предметної галузі студент самостійно ідентифікує щонайменше дві сутності та їх властивості.

- [x] 3. Для ідентифікованих сутностей студент проєктує та реалізовує веб-API, що повинно повністю відповідати принципам REST та яке надає визначені студентом операції для роботи з цими сутностями. Студент може використовувати будь-який із підходів до проєктування API: `contract first` чи `code first`.

- [x] 4. Спроєктоване та реалізоване REST API повинно обов’язково надавати наступні операції для кожної сутності:
  - [x] отримання списку всіх сутностей;
  - [x] отримання певної сутності за її ідентифікатором;
  - [x] додавання нової сутності;
  - [x] оновлення існуючої сутності;
  - [x] видалення всіх сутностей;
  - [x] видалення певної сутності за її ідентифікатором.

- [x] 5. Якщо ідентифіковані студентом сутності пов’язані між собою зв’язком `один-до-багатьох` (наприклад, у одного користувача може бути багато записів у блозі) або `багато-до-багатьох` (наприклад, у одного автора може бути багато книжок і у книги може бути декілька авторів), тоді сутності також повинні мати операції для отримання пов’язаних сутностей (отримання всіх записів у блозі користувача, отримання всіх книг автора тощо).

## Вимоги до програмного забезпечення

- [x] 1. Для реалізації програмного забезпечення в ході виконання комп’ютерного практикуму може використовуватися будь-який стек технологій:
  - [x] мова програмування; Golang
  - [x] вебфреймворк; Gin

- [X] 2. Програмне забезпечення, реалізоване в ході виконання комп’ютерного практикуму, не повинно використовувати постійне сховище (базу даних) для зберігання сутностей.
  
  - Допускається:
  - [X] просте зберігання сутностей у пам’яті;
  - [X] зберігання сутностей у текстових файлах.

- [x] 3. Реалізоване програмне забезпечення обов’язково повинно надавати інтерфейс Swagger (або аналог) для візуалізації та роботи з реалізованим REST API.
```bash
swag init -g cmd/api/main.go
```
